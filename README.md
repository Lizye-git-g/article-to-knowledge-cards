# make-knowledge-cards

一个开源的 Agent Skill:把文章转换成知识卡片,让读者用最少时间掌握核心知识,并支持随时复习自测。

## 解决什么问题

- **文章太长,核心知识被淹没**:读完一篇长文后,真正值得记住的往往只有几个知识点,分散在叙事和铺垫里。这个 Skill 把文章压缩成 5-8 张卡片,每张一个知识点,可以直接用于复习。
- **AI 摘要容易编造和凑数**:让模型直接做摘要,常见两个毛病——补充原文没有的"合理"细节,以及为了凑数量把同一个点拆成好几张卡。这个 Skill 用明确的规则(铁律)约束这两类行为:忠于原文、不凑数量、一卡一点、去重。

## 主要功能

- 把粘贴的文章文本或本地 Markdown / TXT 文件转换成 **5-8 张知识卡片**;信息不足时如实输出更少的卡片,绝不硬凑
- 每张卡片包含四个字段:**标题、核心知识(40 字内)、简明解释、例子或自测问题(附答案)**
- **忠于原文**:事实必须来自原文或由原文直接推导,不补充原文没有的数据、机制解释、适用人群或行动建议
- **一张卡片一个知识点**;同一知识点多处出现时合并;机制与其直接推论优先合成一张卡片
- **语言跟随原文**:中文文章出中文卡片,英文文章出英文卡片
- 兼容 Claude Code(标准 SKILL.md)与 OpenAI Codex(`agents/openai.yaml` 界面配置)

## 安装

**Claude Code**

- 个人使用:把 `skills/make-knowledge-cards` 整个目录复制到 `~/.claude/skills/` 下
- 项目使用:复制到项目内的 `.claude/skills/` 下

**OpenAI Codex**:复制到 `~/.codex/skills/` 下。

**随仓库分发**:仓库中保留 `skills/` 目录结构即可,Codex 用户可直接使用,Claude Code 用户复制或链接到 `.claude/skills/`。

## 使用方法

直接把文章粘贴给 Agent,或给出本地 `.md` / `.txt` 文件路径:

```
把下面这篇文章做成知识卡片:

<粘贴文章内容>
```

```
把 docs/my-article.md 做成知识卡片
```

如需保存为文件,追加一句:

```
保存为 http3-knowledge-cards.md
```

## 输入输出示例

**输入**(article-1-http3.md,节选):

> HTTP/3 不再使用 TCP,而是运行在 Google 提出的 QUIC 协议之上,底层传输改用 UDP。
> 为什么放弃 TCP?核心原因是队头阻塞:TCP 保证字节流按序到达,只要有一个数据包丢失,
> 后续所有数据包都必须等这个包重传后才能交给应用,即使它们属于互不相干的网页资源……

**输出**(共 7 张卡片,节选前 2 张):

```markdown
### 卡片 1:HTTP/3 弃用 TCP,改用基于 UDP 的 QUIC

**核心知识**:HTTP/3 运行在 QUIC 之上,底层传输从 TCP 改为 UDP

**简明解释**:HTTP/3 是 2022 年发布的第三代 HTTP,与前两代最大的区别是不再使用 TCP,
而是运行在 Google 提出的 QUIC 协议之上,底层传输改用 UDP。这是它一切性能优势的基础。

**自测**:HTTP/3 与 HTTP/2 最根本的区别是什么?
答:不再使用 TCP,而是运行在基于 UDP 的 QUIC 协议之上。

### 卡片 2:队头阻塞源于 TCP 按序交付,HTTP/2 多路复用未能解决

**核心知识**:队头阻塞源于 TCP 按序交付,HTTP/2 多路复用也未能解决

**简明解释**:TCP 保证字节流按序到达,只要有一个包丢失,后续所有包都要等它重传后才能
交给应用,哪怕它们属于互不相干的网页资源,这就是队头阻塞。HTTP/2 曾试图用多路复用
绕过它,但 TCP 本身按序交付,丢包时整个连接的所有流仍一起被卡住。

**例子**:一条 HTTP/2 连接同时加载头像、样式表和新闻图片:新闻图片的数据包丢了,
由于 TCP 按序交付,头像和样式表后续的包也必须排队等它重传,整个页面的加载都被拖慢。
```

英文文章同样支持,输出英文卡片(已用 Paul Graham《How to Do What You Love》实测,共 8 张)。

## 适用范围

| 支持 | 暂不支持 |
| --- | --- |
| 粘贴的文章文本 | URL 网页抓取 |
| 本地 Markdown / TXT 文件 | PDF |
| 中文 / 英文文章 | Anki 导出、图形界面 |

## 开发与验证

- Skill 由 openai/skills 仓库的官方 `init_skill.py` 初始化生成,无多余脚本
- 结构验证(openai/skills 官方脚本,中文 Windows 需加 `PYTHONUTF8=1`):

```
python quick_validate.py skills/make-knowledge-cards
# Skill is valid!
```

- 已用四类文章测试:技术文章、科普文章、短论说文、英文长文。带 Skill 的输出
  18/18 项检查通过(卡片数、四字段完整、忠于原文、一卡一点、不重复、覆盖核心点);
  不带 Skill 的基线会编造细节、把 5 个知识点的短文拆成 7 张卡。
