# 知识卡片生成器 (Make Knowledge Cards)

把一篇文章压缩成 5-8 张可复习的知识卡片,让用户用最少时间掌握文章的核心知识。

## 输入

**支持:**
- 用户直接粘贴的文章文本
- 本地 Markdown / TXT 文件:用 Read 工具读取,长文件分段读完再开始制作

**不支持(明确告知用户,并说明支持范围):**
- URL 网页抓取、PDF、Anki 导出、图形界面

## 制作流程

先通读全文再动笔,不要只读开头就下结论。然后按以下步骤制作:

1. **识别知识点**:找出文章中所有可独立学习的知识——概念、机制、规则、方法、反直觉的结论。叙事细节、背景铺垫、作者感想不是知识点。
2. **筛选重要项**:只保留真正重要的。判断标准:
   - 是文章的核心观点或核心机制,而不是支撑性的细枝末节
   - 对读者有普遍价值(可迁移、可复用),不是只在本文语境里有意义的琐碎信息
   - 自问"如果读者只能记住一点,该是哪一点"来排序;反直觉、易记错的内容优先于常识复述
3. **去重**:同一知识点在多处出现时合并为一张卡片,取表述最完整、最清晰的一处。
4. **切分**:一张卡片只讲一个知识点。如果"一个知识点"里实际包含两个可独立学习、独立回忆的要点,拆成两张卡片。但一个机制和它的直接推论(如"注意力残留"与"多任务因此做不好")优先合成一张卡片——推论依赖机制才能理解,拆开反而显得重复;只有当推论本身有独立的应用场景时才拆开。
5. **定数量**:目标 5-8 张。
   - 知识点超过 8 个:按重要性砍掉最次要的,保留前 8。
   - 知识点不足 5 个:如实输出较少的卡片(比如 3 张),并在开头说明"该文核心知识点共 N 个"。绝不为了凑数拆分、重复或编造。
6. **写卡片**:使用下方固定格式,按重要性从高到低排序。
7. **自检**:对照"铁律"逐条检查全部卡片,发现问题立即修改,再输出。

## 卡片格式

每张卡片必须使用以下模板,四个字段一个都不能少:

```markdown
### 卡片 N:标题

**核心知识**:一句话概括这个知识点,40 字以内,去掉修饰直接说结论

**简明解释**:2-4 句,讲清"是什么、为什么重要、怎么用"。用自己的话写,不照抄原文长句

**例子/自测**:二选一
- 例子:一个具体场景。场景可以虚构,但其中体现的知识必须来自原文
- 自测问题:一个必须结合该知识点才能回答的问题,下一行给出答案(答:...)。问题与答案都不得超出原文信息
```

标题只写知识点本身(如"睡眠压力来自腺苷积累"),不写"关于""之我见"之类的词。

## 铁律

1. **忠于原文**:卡片中的事实必须来自原文,或由原文信息直接推导。不得补充原文没有的数据、研究、人名、结论,也不得补充原文没有的机制解释、适用人群、行动建议——哪怕它们听起来合理,最常见的编造正是这种"顺手的补充"。这是最重要的规则:用户拿卡片复习时分不清哪些是原文、哪些是编造的,编造会直接损害卡片价值。
2. **一卡一点**:每张卡片只讲一个知识点。两个检查方法:卡片中删掉任何一句后,其余部分仍能独立成立;若两张卡片的例子/自测互换后不显得别扭,说明它们本是同一个知识点,应当合并。
3. **不凑数量**:信息不足时,卡片少于 5 张是正确行为,不要硬凑。
4. **不重复**:所有卡片的"核心知识"互不重叠。允许引用同一事实,但每张卡片必须聚焦不同的一点。
5. **语言跟随原文**:中文文章出中文卡片,英文文章出英文卡片;用户指定语言时按用户要求。

## 输出

- 默认在回复中直接输出卡片,开头一行说明总数(如"共 6 张卡片")。
- 用户要求保存时,写为 `<文章主题>-knowledge-cards.md` 文件。
- 不输出与卡片无关的评论、总结或寒暄。
